# AgentBroker release output binding

AgentBroker publication uses an explicit source-content build and an accepted output receipt. Preserve published Git history. The privacy changes for future packages also cover ModuleKit in other modules through the official build and ZIP routes; they do not rewrite old ZIPs or make other modules use AgentBroker's source stamps and receipt workflow.

Use PowerShell 7.6.5 and the SDK pinned by global.json. The configured locked restore policy has one nuget.org feed and may use the network. It is not an offline restore promise.

1. Finish reviewed production/version changes, the canonical Host build and ordinary gates that compile the release graph. Run the seven deterministic harnesses once and measure their actual inventories. Restore all controlled source/output changes. Freeze the exact final compiled/watched inputs before the stamped build. Later counter-only PowerShell changes need their affected contract and narrow control, with their source delta captured separately.
2. Run packaging/AgentBrokerReleaseProvenance.ps1 -Mode Prepare and retain its manifest, source-content digest and parent commit. Reuse and verify an exact already-prepared manifest rather than blindly repeating its CreateNew step. Run -Mode Build -ManifestPath ... -ExpectedSha256 ... -ExpectedParent .... This is the final ordinary compilation of the accepted baseline. Its global properties include SkipAgentBrokerWorkerPublish=false, DesignTimeBuild=false, BuildProjectReferences=true and Optimize=true; ambient flags must not skip references or fresh Worker publication.
3. Retain the returned immutable output receipt path and raw SHA-256. Run qualified nonbuilding checks on that exact stamped output: the public AgentBroker module gate, -Mode VerifyOutput -OutputReceipt ... -OutputReceiptSha256 ..., and standalone tests/Test-AgentBrokerPackaging.ps1 -CheckPayload under PowerShell 7. The standalone packaging check avoids rebuilding the seven harnesses. Use an owned mixed-case ToKeN TEMP parent for the module gate's path-tolerance case. Record the actual module count, loaded-module witness and copied-Worker payload witness; a copied payload witness does not prove Worker execution.
4. Create a provisional bound ZIP for qualification with packaging/New-ModuleDistZip.ps1 -ModuleId agentbroker -SourceDirectory <canonical Release module output> -DestinationPath <candidate ZIP> -AgentBrokerOutputReceipt ... -AgentBrokerOutputReceiptSha256 .... Use a new, absent destination for this first creation, when no candidate hash exists yet. This verifies output before and after compression and matches every entry to the receipt. Freeze the returned exact ZIP hash. Any repeat of this command, including one targeting the canonical path or making a repack comparison, must also pass -ExpectedAgentBrokerZipSha256 <retained original candidate hash>. A direct byte copy to the canonical path must verify its source and destination against that same retained hash. Never replace the retained anchor with a hash recalculated from a possibly changed ZIP. This ZIP is available to scoped artifact controls; it is not accepted for publication yet.
5. Run the required scoped controls against that bound ZIP, using E-owned copies where possible. Any approved control that temporarily builds a variant must restore the exact original source and payload bytes/metadata, then verify the restored receipt and healthy output. Confirm the original provisional ZIP still has its recorded bytes/hash. Only after control qualification, use that same unchanged ZIP for supported real installation and installed acceptance before any source commit. It becomes the accepted candidate only when those real-app checks pass. Follow the installer's canonical candidate-path requirement; do not substitute loose DLLs, an active variant, an ordinary rebuild or a later re-zip.
6. After real-app acceptance, commit the reviewed source and compare the frozen inputs with the exact committed Git bytes (source F2 evidence). Publish the payload and catalog from the same accepted ZIP using packaging/New-ModulePublish.ps1 -ModuleId agentbroker -SkipBuild -AgentBrokerOutputReceipt ... -AgentBrokerOutputReceiptSha256 ... -ExpectedAgentBrokerZipSha256 ... and the approved publication options. Preserve the source/payload/catalog commit bindings. Run the required exact-range privacy check (F4) on that final composition before pushing it. Retain the subsequent exact-head CI and post-push audit results.

The Build metadata check reads six owned managed assemblies and the Worker apphost without executing their code. It verifies release metadata and the exact public source-content/parent-commit stamps on the module and Worker. ModuleKit keeps its required embedded portable PDB, with public /_/ document mapping and no SourceLink or embedded-source records. The other five owned assemblies must have no CodeView or embedded portable PDB record. Owned PDB sidecars are refused. The receipt binds the complete packaged filename, size and SHA-256 set, excluding .pdb and .lib as the ZIP utility does.

Receipt names are sourceSHA.rawReceiptSHA.output.json. The second component is the SHA-256 of the complete serialized receipt bytes and equals returned OutputReceiptSha256; it is not InventorySha256. The inventory remains a separate payload field. Exact repeats reuse the same immutable receipt. A legitimate tooling-only requalification can create a different receipt with the same source/payload inventory because the full receipt includes operational authority.

newModulePublishSha256 and newModuleDistZipSha256 bind the current publisher and ZIP scripts as operational receipt authority. Those generic scripts are outside the stamped production source identity and AgentBroker payload watch set, so a later generic tooling commit does not itself force an AgentBroker payload release. Changes during an in-flight release still refuse with PROVENANCE_OUTPUT_AUTHORITY_CHANGED against the old receipt. Requalify the actual output and tooling, retaining the new immutable receipt and accepted ZIP bindings.

Hash inputs are exact scalar values: source-content and output-receipt hashes are 64 uppercase hexadecimal characters; the parent is 40 lowercase hexadecimal characters. ExpectedAgentBrokerZipSha256 accepts either hexadecimal case and normalizes it to uppercase. Trailing whitespace or a newline is refused, not trimmed. Use values returned by the qualified build/candidate steps rather than recomputing an accepted anchor from a file that may have changed.

AgentBroker publication without -SkipBuild refuses before building or publishing. The publisher checks committed/clean source and operational paths, receipt authority and accepted ZIP bytes before the ZIP step and before its commit/manual-commit split. These dirty-source checks do not establish independent review or source F2. With -Commit, the checks precede the payload commit performed by that invocation. Without -Commit, an uncommitted ZIP causes exit 3 and manual instructions; that check does not protect a later manual commit. Repeat the required authority checks immediately before committing, or rerun the approved -Commit route.

Any later build.ps1, clean gate or ordinary module build can replace the canonical stamped output. Restore exact saved output, or rerun only the stamped Build with the original manifest. Continue with the old acceptance only if the output receipt and bound ZIP reproduce the accepted values. Different payload or ZIP bytes require a new candidate and new installed acceptance. A compression-runtime change is not permission to replace the accepted ZIP silently.

For future generic module packages, build.ps1 and the generic publisher disable SourceLink and embedded source generation. The ZIP route validates ModuleKit's mapped embedded symbols and binds the checked ModuleKit bytes to the ZIP entry wherever that library is present. This is a forward package requirement, not a retrospective clean-history claim.

This is a reviewed AgentBroker source closure, not an identity for every repository or SDK input. Local output binding does not establish installed readiness, authorize publication, or protect against an arbitrary concurrent filesystem writer. The real-app, privacy, freshness and publication checks remain required.

# v1.0.0: rename to Desktop AI Companion, new repo, fresh history

## Why this exists

The product pivoted. These are not pets: converted Shimeji skins overwhelmingly represent human characters,
so "pet" mislabels most of the library. The user-visible rename to **Desktop AI Companion** already landed
(product name, tray, panes, Companion Studio). This document covers the rest, which is everything that could
not be renamed while staying backward-compatible.

**The reason to do it now and not later.** Several of these names are compatibility surfaces: settings keys,
the catalog's `pets` key, on-disk directory names, the plugin ABI. Renaming any of them normally requires a
migration or a breaking major bump. A version rebase to 1.0.0 with a **mandatory clean install** makes all of
them free, exactly once. After 1.0.0 ships, the window closes.

Decisions taken with the maintainer:

| | |
|---|---|
| Repo | `bigfnj/desktop-ai-companion` (kebab-case, reads cleanly in raw URLs) |
| Depth | **Tier 3** — everything, including the plugin ABI and settings keys |
| History | **Fresh**, single initial commit. Old repo deleted after v1.0.0 verifies |
| Version | 1.9.16 → **1.0.0** |

## The six things that will break this if missed

1. **`MinHostVersion` on every module.** All six catalog modules declare 1.4.0 to 1.9.9. Rebase the host to
   1.0.0 and **every one of them refuses to load** — a silent, total loss of function that looks like the
   module system being broken. All seven (six + TestModule) go to `1.0.0`.
2. **Rebasing module versions down is only safe because of the clean install.** The in-app Update button
   compares the catalog's version against the installed one, so a machine holding petstudio 1.7.0 against a
   catalog offering 1.0.0 sees itself as already ahead and is never offered the update again. Nothing on
   disk survives the clean install, so no machine is ever in that state — but that is the *reason* it is
   safe, not an accident, and it stops being true the moment anyone installs 1.0.0 modules over an old tree.
3. **The MSI needs a NEW `UpgradeCode`.** 1.0.0 is a *downgrade* of 1.9.16, so with the current UpgradeCode
   the installer refuses to install over it. A new code makes it a separate product, which is correct, and
   is what forces the clean install this whole plan depends on.
4. **The catalog cannot verify itself before it is pushed.** `catalog.json` will reference
   `raw.githubusercontent.com/bigfnj/desktop-ai-companion/master/...`, which 404s until the repo exists and
   the push lands. Order: create repo → push → *then* verify URLs. Do not treat a 404 before the push as a
   defect.
5. **Attribution does not travel with the fork link.** The current repo is a fork of
   `Adrianotiger/desktopPet`; the new one deliberately is not. What satisfies the upstream licence is
   `LICENSE`, `THIRD_PARTY_NOTICES.md` and `grimoire/01-history-and-lineage.md`, all of which are tracked
   files and must be present in the initial commit. Verify, do not assume.
6. **The pet XML schema is NOT renamed.** `animations.xml` element and action names are the Shimeji
   conversion contract and 53 published companions use them. Renaming them invalidates the entire corpus.
   Same for the built-in id `eSheep`: that is a character name, not the word "pet".

### Traps the enumeration found (none of these were in the first draft)

**Renames that break SILENTLY — no compiler error.** Cross-assembly reflection by type-name string. A
normal rename leaves these pointing at types that no longer exist, and the failure shows up as a self-test
skipping or a soak finding nothing, not as a build break.

| string | file |
|---|---|
| `"DesktopAICompanion.FormCompanion"` (via `GetType(..., true)`, so it **throws**) | `RuntimeHardeningSelfTest.cs:414` |
| `"DesktopAICompanion.PetStudioModule.PetStudioWindow"` | `tests/DesktopAICompanion.WindowSoak/Program.cs:41` |
| `"…PetStudioModule.AnimCapabilitySelfCheck"`, `"…PetStudioTheme"`, `"…BehaviourChainSelfCheck"`, `"…PetAnalyzer"`, `"…PetStudioPaths"` | `PetStudioModuleSelfTest.cs:78,104,174,215,304` |
| `"DesktopAICompanion.PetStudio.animations.xsd"` (embedded-resource manifest name) | `modules/PetStudio/EngineShim.cs:59` |

**Two mutex-name literals that must stay identical to each other.** `@"Global\DesktopAICompanion."` appears in the
host at `AppSettingsStore.cs:1232` and in ModuleKit at `CrossSessionLock.cs:40`. They are the same lock.
Rename both or neither; renaming one silently stops the host and its modules from seeing each other's lock.

**`Pets/` with a capital P is a live URL path segment**, not just a folder: every one of the 53 published
skins resolves through `…/master/Companions/<id>/animations.xml`, and `RemoteCatalog.cs:362` asserts that exact
segment. The directory, the assertion, the 53 catalog URLs and `Companions/companions.json` move together or not at all.
Free to rename here only because the new repo republishes the catalog from scratch.

**A case-insensitive sweep will corrupt three proper nouns.** `Adriano Petrucci` (the upstream author),
`https://esheep.petrucci.ch/` (the animations XML **target namespace**, in the XSD and every skin), and the
same host in the About dialog. "Petrucci" contains "petru". Any `pet` → `companion` replacement must be
whole-word and must exclude these explicitly.

**More persisted keys than the first draft listed.** Beyond the 12 in `AppSettingsStore`:
`AiSettings.PetName` (a PascalCase field persisted into `ai-settings.json`), Reminder's per-slot
`SlotKey(i, "pet")` producing `slot1.pet`, the resx resource keys `removepet` and `petspeech`, the four
host options-pane field ids (`petsAtStartup`, `petSounds`, `petUpdateCheck`, `defaultSpeakingPet`), and the
fortune pack **file magic headers** `#!desktop-pet-fortunes-v1` / `-v2` and
`#!desktop-pet-classifier-parity-v1`.

**`CatalogKinds.Pet = "pet"` is an ABI wire value**, not just a constant: modules pass it to
`FetchCatalogItemsAsync`. The identifier and the string can both change, but only because every module is
rebuilt in the same pass.

**`docs/fti/FTI_112.json` is a generated full-text index** containing `pet`, `pets`, `petname` and
`petrucci` as tokens. Regenerate it; never hand-edit it.

**Five separate `FakeCompanion` types.** One public in `ModuleKit/Testing/Fakes.cs:102` and four private nested

### A trap Phase 4 actually hit: catalog hashes do not survive a new repository

`New-ContentCatalog.ps1` hashes `git cat-file blob HEAD:<path>` -- the COMMITTED BLOB -- because that is the
byte stream `raw.githubusercontent.com` serves. A new repository re-normalises line endings on commit
(`.gitattributes` says `* text=auto eol=lf`), so a file that was stored with CRLF in the old repository is
stored as LF in the new one and its **blob hash changes**.

Measured, not predicted: **3 of the first 8 companions mismatched** after the initial commit -- exactly the
files git had warned about with "CRLF will be replaced by LF". Downloads of those skins would have failed
their integrity check while the rest worked, which is the worst shape of failure to diagnose later.

The fix is one line of process, and it belongs in any future repository move: **regenerate the catalog
INSIDE the new repository, after the initial commit, then amend.** All 211 assets (53 companions, 152 packs,
6 modules) then verify, and an end-to-end download of one of the three previously-mismatched skins matches
what GitHub actually serves.

## Parallel tracks

The core rename (Phase 2 steps 1–3) is **serial by nature**: it is one compile graph, and two agents editing
it concurrently produce conflicts that look like rename errors. What genuinely parallelises:

| Track | Work | Depends on |
|---|---|---|
| **A** | Phase 0 preservation; attribution audit | nothing |
| **B** | Docs + `grimoire/` + `templates/` prose sweep | nothing (separate files) |
| **C** | Build the Phase 1 rename map by enumerating the code | nothing |
| **D** | New repo creation and configuration (Phase 4 setup only) | nothing |
| **E** | Installer + packaging + CI (Phase 2 steps 4–5) | step 2 (exe name) |
| **F** | Verification: gate under each shell, both soaks | Phase 2 complete |

A, B, C and D run alongside the serial core. E follows the exe rename. F fans out at the end.

## Verification standard

Unchanged from this repo's conventions, and it matters more here than usual because a rename touches
everything and reads as harmless: the gate, source invariants via the `Get-MethodBody` slicer, in-process
self-tests behind `--flags`, and **every new or changed guard mutation-tested with the FIRED lines recorded
in the commit**. Two specific traps this repo has already paid for:

- A source invariant asserting a **bare identifier** is satisfied by a comment naming it. Assert the code
  form, on comment-stripped text.
- A mutation harness that restores with `git checkout --` destroys uncommitted work and then reports
  "FIRED" for the wrong reason. Baseline from the working tree and assert the code under test is present
  before mutating.

## Rollback

Until Phase 6, rollback is free: the old repo still exists and still serves its catalog. After Phase 6 there
is no rollback, which is the reason Phase 6 is last and gated on a passing smoke test rather than on a
passing build.

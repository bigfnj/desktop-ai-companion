# AgentBroker certificate continuity design

Owner decision, 2026-11-07: design authenticated automatic certificate rotation for N-audit-1106-079. The chosen design renews TLS certificates on the existing nonexportable user CNG key. The original public certificate/hash remains the immutable paired application identity. Private-key rotation and compromised-key recovery remain separate operations. Implementation, combined regression with 3178 assertions, the actual loader's 385 checks and official installed 1.9.0 acceptance are complete; the [campaign ledger](../agentbroker-180-validation.md) records artifact identity and the pending publication separately.

| Approach | Offline behavior | Decision |
| --- | --- | --- |
| Staged exact-leaf pin update over the old authenticated channel | Peers offline through old-leaf expiry miss the update. Arbitrary absence needs retained history, a stable authority or explicit recovery. | Insufficient alone. |
| Certificate-carried signed old-to-new key transitions | Missed transitions need bounded history or a retained original signer, with durable retirement and rollback policy. | Larger than the certificate-expiry repair. |
| Original public identity anchor and renewable same-key leaf | An upgraded peer holding only its original exact certificate hash can authenticate after any number of missed renewals. | Selected; constant proof size and no peer pin-update transaction. |

The existing CA=false certificate lacks keyCertSign and remains an application key anchor. It is not a PKIX issuing CA or system trust root. A proper CA/separate-leaf-key migration would require another authenticated transition. [RFC 5280 constraints](https://www.rfc-editor.org/rfc/rfc5280.html#section-4.2.1.9), [.NET custom trust](https://learn.microsoft.com/en-us/dotnet/core/extensions/sslstream-best-practices#custom-certificate-trust).

The protocol UUID `421ce52f-8f48-4206-899b-f11672d7d5a6` fixes attribute type `2.25.87879080473710008048449786743199618470` using its network-order unsigned integer. The standard noncritical SubjectDirectoryAttributes extension (2.5.29.9) contains exactly one Attribute of that type and a SET OF exactly one DER SEQUENCE { version INTEGER(1), anchorCertificate OCTET STRING }. The octets are the complete original certificate. The UUID attribute is parsed only by managed ASN.1. [RFC 5280 subject attributes](https://www.rfc-editor.org/rfc/rfc5280.html#section-4.2.1.8), [official ITU UUID/OID allocation](https://www.itu.int/en/ITU-T/asn1/pages/uuid/uuids.aspx), [.NET extension API](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.x509certificates.x509extension).

The [pure verifier](../../tools/AgentBroker.Worker/Security/CertificateContinuity.cs) performs no filesystem, key-store, network, cache or ambient-time access. Its APIs are `IsValidAnchor(anchor,brokerId)`, `CreateAnchorExtension(anchor,brokerId)` and `MatchesPinnedCertificate(presented,brokerId,anchorSha256,now)`. Bounds are 16384 anchor bytes, 16512 raw attribute-container bytes and 32768 leaf bytes. A proof-free original cannot contain another continuity container. No recursive proof/history growth is permitted.

Proof-free live leaves retain exact full-certificate pins. Renewed leaves require one strict version 1 proof whose original DER has that exact paired hash. Both certificates must match the expected broker ID and original RSA 3072 end-entity usage profile; their complete SubjectPublicKeyInfo values must match. Only the live leaf must be currently valid according to the explicit local time. Historical anchor expiry never makes an expired live certificate acceptable. [Public-key export](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.asymmetricalgorithm.exportsubjectpublickeyinfo?view=net-10.0).

Self-signature verification uses exact encoded TBSCertificate bytes, matching inner/outer SHA256-with-RSA AlgorithmIdentifiers, zero unused signature bits and RSA-PKCS1. Signed bytes are not reserialized. Duplicate, malformed, critical, unsupported, oversized and nested recognized proofs refuse without permissive fallback. [.NET DER reader](https://learn.microsoft.com/en-us/dotnet/api/system.formats.asn1.asnreader?view=net-10.0), [.NET RSA verification](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.rsa.verifydata?view=net-10.0).

Mutual TLS still proves private-key possession; public anchor bytes or a matching name alone cannot. TLS 1.3 uses CertificateVerify; platform secure TLS defaults remain. [RFC 8446](https://www.rfc-editor.org/rfc/rfc8446.html#section-4.4.3), [.NET TLS defaults](https://learn.microsoft.com/en-us/dotnet/core/extensions/sslstream-best-practices#select-tls-version).

PeerTrust.CertificateSha256, advertisements, manual invitations, comparison-code inputs and reconnect use the stable original anchor hash. [Federation](../../tools/AgentBroker.Worker/Federation/PeerFederation.cs) shares the verifier for inbound peer authentication, pairing callers and outbound TLS. Discovery cannot replace a pin. Existing current-authorization checks remain mandatory around awaits and before admission; proof never restores a revoked peer or grants transitive trust. An older still-valid same-key leaf represents that same identity; individual leaf-key retirement is outside this design.

Federation advertisement, pairing and message JSON schemas gain no fields. The local protected identity metadata changes from v1 to v2 after renewal, and older workers refuse that metadata. Downgrade is not transparent. An upgraded offline peer can recover automatically by validating the carried original certificate against its stored hash. Old peers reject renewed leaves and require upgrade; no expired-leaf fallback exists. Lost original metadata/key ownership fails closed. Certificate validity is evaluated against each broker's local clock; clock skew can prevent TLS. Peer-observed time never overrides certificate validity.

The implemented lifecycle renews at startup when 90 days or less remain and checks hourly for a graceful renewal stop. Worker recreation follows awaited disposal, with external stop, parent death and durable failure taking precedence. This avoids live certificate swap/disposal races. The module version is 1.9.0.

[Focused contracts](../../tests/AgentBroker.Worker.Tests/CertificateContinuityChecks.cs) cover original pins, historical/live expiry, same-key renewal, wrong hash/ID/key, deterministic time, integrity/profile refusal, malformed/versioned/critical/nested proofs, bounds and constant proof size. The unchanged helper and contract files passed 22 checks in an isolated standalone assembly, then passed 22 after each of three exact restorations. Removing SPKI equality failed CERT_SPKI_CONTINUITY; removing the carried-anchor hash failed CERT_PROOF_EXACT_HASH; bypassing self-signature verification failed CERT_SELF_SIGNATURE. Each control failed exactly its named assertion. Seven no-incremental builds advanced artifact timestamps, mutant artifact hashes changed, execution emitted the required witness and matched the just-built artifact hash, and all helper source bytes were restored.

The standalone assembly compiled BrokerIdentity only for the shared assembly-hash witness; it did not instantiate an identity, access the user key store, contact a peer or build integration. Its hash marker identifies that standalone assembly, not an installed Worker. Subsequent real TLS exchanges, integrated regression and actual installed acceptance are recorded separately in the campaign ledger.

The first standalone healthy run compiled successfully but failed the renewed-leaf positive: Windows native extension enumeration could not represent the direct large-arc UUID extension OID. No mutant ran in that attempt. The standard subject-attribute wrapper above then passed all 22 isolated checks. This concrete shipped-runtime incompatibility changed serialization; it did not weaken the paired hash, key or broker bindings. Failed and diagnostic receipts are retained separately from subsequent qualification.

## Lifetime and call-chain review

The module's serialized lifecycle gate keeps restart/stop ownership in one supervisor at a time. Owned children use retained process handles; standby never stops another broker. Cancellation sources are disposed after their corresponding task completes. UI callbacks check shutdown/generation and status observation order before applying results. Pairing questions are withdrawn on restart/shutdown and late answers recheck the current offer and generation. The shutdown assertion now identifies the current run instead of counting earlier cleanup.

The aggregate approval bridge retains only a bounded count/timestamp payload. AgentFlow publishes on the UI thread, refuses late publication after shutdown begins and withdraws its retained value during shutdown. AgentBroker detaches the context event and disposes its bounded expiry timer. Already queued timer callbacks check shutdown and reread current state, rather than restoring an old observation. Worker restart forwarding checks both retained context and the new worker snapshot. The module does not use session declarations or custom titles as authorization; those remain exact-address, local hints in the Worker tools reviewed by the core lane.

No additional confirmed dead call, unbounded retention or lifecycle defect was found in these reviewed module/bridge paths beyond the supervision and clock findings above. That is a finite source/fixture result, not a resource-soak or leak-freedom claim. No performance improvement is claimed. The owner's identity-expiry decision and its completed engineering and installed acceptance are recorded above; configured GUI and physical acceptance limits remain separate.
